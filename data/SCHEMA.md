# Формат учебного пакета

Бизнес-правила задаёт [контракт курса](../course/contracts.md), назначение задач —
[карта данных](../course/data-readiness.md). Все пути ниже относительно `course_pack/`.

| Файл | Назначение |
|---|---|
| `inputs/<task>.jsonl` | Входные конверты без эталонов |
| `scenarios.jsonl` | Полные сценарии для тестового адаптера и самопроверки |
| `expected/<task>.jsonl` | Эталоны и основания по case_id |
| `eval/` | Экспорты классификации и извлечения для экспериментов |
| `reference/*.json` | Фиксированные прайс, зоны, клиенты и слоты |
| `kb/manifest.json` | Источники, версии, сроки действия, права, статусы и хеши |
| `fixtures/` | Управляемые дефекты и файлы для ingestion |
| `manifest.json`, `splits.json`, `coverage.json` | Состав, целостность, семейства и покрытие требований |

## Конверт

`case_id` идентифицирует сценарий, `family_id` объединяет родственные ситуации,
`split` принимает `train`, `dev`, `test` или `regression`. `input` содержит данные
задачи. Полный сценарий дополнительно содержит `task`, `expected`, `basis`,
`tags` и статус проверки. Эти поля служат тестовому адаптеру, а не модели.

`load_course_inputs(task, split=...)` проверяет хеш входного файла по manifest.
`load_course_cases(task, split=...)` читает полные сценарии для сравнения результатов.
Пути считаются от файла загрузчика, независимо от рабочего каталога.

## Входы по задачам

- M1: `end_to_end.input.text` → `raw_text`; `channel`, `message_id`,
  `client_contact` → одноимённые поля API. Служебный конверт целиком не отправляется.
- M2: модель получает `input.text`. `client_contact` подставляет приложение;
  `expected.model_fields` оценивает извлечение, `expected.fields` — итог приложения.
- M3/M8: тестовый адаптер воспроизводит события и часы; ожидаемые состояния и
  эффекты сравнивает после выполнения приложения.
- M4: в `eval/classification_*.jsonl` поле `input` — текст, `type` и `priority` —
  метки. Готовые train/dev/test разделены по семействам; test не используется для настройки.
- M5: справочники загружаются из JSON. `scope`, `valid_from`, `valid_to`, `status`
  в KB manifest проверяет сервер. Файлы `legacy_formats` имеют статус quarantine.
- M6/M7: доверенную идентичность и сбои задаёт тестовый адаптер. Поле
  `forced_model_proposal` используется только в контролируемом моке диспетчера.

Названия и значения решений перечислены в §4–§7 и §14 контракта курса.
Набор синтетический, test опубликован для самопроверки и не является закрытым экзаменом.
Независимая человеческая проверка разметки пока не выполнена. Предсказания модели,
реальный OCR, нагрузочный прогон и телеметрию получает студент при запуске своей реализации.
