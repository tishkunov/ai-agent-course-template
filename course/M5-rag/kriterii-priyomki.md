# M5 — критерии приёмки

Каждая строка проверяется на коде студента. Локальные фикстуры описаны явно; редактор курса
не создал новый датасет. Для unit/integration подменяется клиент M2/конкретный loader;
качество retrieval и генерации оценивается отдельно реальными предсказаниями.
LangGraph M6, кеш M8 и панели M9 не нужны для сдачи M5.

| Требование | Предусловия | Вход и действие проверяющего | Наблюдаемый результат | Признак ошибки |
|---|---|---|---|---|
| M5.1 | Один чистый импорт, исходники неизменны | Дважды импортировать те же price/clients/zones; добавить в тестовый вход пустую цену и конфликт ключа | Количество рабочих строк не растёт; плохие строки перечислены с причиной | Дубль, нулевая цена вместо неизвестной, скрыто потерянная строка |
| M5.2 | Таблица форматов cases.md; известные scope отдельно | Извлечь по файлу каждого формата; подменить один loader исключением; подать документ без metadata | Фрагменты совпадают с таблицей; сбой виден; unknown-scope не в доступном индексе | Пустой текст скана объявлен успехом; неизвестный scope стал all |
| M5.3 | Один конфиг нарезки и два примера задания | Нарезать дважды, сравнить ID/текст; проверить условие вместе с исключением и число с единицей | Повтор идентичен, основания не разорваны; сравнение второго размера записано | Исключение или единица потеряны |
| M5.4 | Индекс и фикстура R-C4; две записи с одинаковым текстом и разными scope | Обновить один источник и отдельно его scope; удалить другой; вызвать сбой построения | Старые чанки не активны; права обновлены; соседние источники не затронуты | Старое условие/право осталось доступным; половина версии опубликована |
| M5.5 | FAQ и договор явно допущены по cases.md; позитивный поиск договора для 7 успешен | Запустить вопрос про выходные и отдельно чужой договор | Показаны кандидаты с источниками; нужный факт найден; чужого ID/текста нет | Итоговый ответ скрывает наличие чужого кандидата |
| M5.6 | Одинаковые запросы, модель, версия KB и k | Сравнить смысловой запрос и точный термин из задания для двух методов | Одна таблица рангов/времени; одинаковые права; нет дублей | Выбран только удобный запрос или заявлен обязательный прирост |
| M5.7 | Те же кандидаты, зафиксированный реранкер, N=10 | Сравнить порядок/время; отдельно подать 0/1 кандидата и список длиннее N | Обработано не более N; вывод об использовании основан на результатах | Добавлен недоступный кандидат; пустой список вызывает ошибку |
| M5.8 | FAQ и два разрешённых конфликтующих источника; mock M2 отдельно от live | Первый ответ, вопрос без основания, конфликт; затем реальные предсказания по задаче `rag` (40 вопросов) | Источники проверяемы; found=false при отсутствии/конфликте; качество отмечено n/N | Нерелевантный текст принят за доказательство или мок назван качеством модели |
| M5.9 | Явные поля и SQL-фикстуры; retrieval допускает stub | Проверить null услуги; известную неактивную; неизвестный район; район вне зоны без телефона; суммы 15000/15001; цену за единицу без объёма; неоднозначную услугу; отказ SQL | Неизвестное отличается от отрицательного; нарушение выше нехватки; только 15001 выше порога; сбой не даёт авто | Скрытая сумма взята из эталона; null стал «нет в прайсе»; недоступный источник подтверждён |

## Интеграционная сдача

Покажите первый ответ по тексту → отсутствие основания → разбор конфликта → обновление документа →
проверку доступа → SQL-валидацию. Ситуации R-C1–R-C8 из [cases.md](cases.md) проверяют конкретные
этапы: ни одна не заменяется общим утверждением «RAG работает». Исправление адреса инвалидирует
прежнюю зону; повтор проверки использует новый адрес (Q-S04). Вопрос по регламенту не требует адреса
(Q-S06), неполнота отличается от отрицательной проверки (Q-S08–Q-S10), чужие документы исключены
(Q-S14), отказ источника не подтверждает условие (Q-S17).

В сдаче: команда локального запуска; результат рабочего пути и значимого сбоя; версии конфигурации,
моделей и промптов; таблица сравнения поиска; n/N и ограничения эталонов; отдельное ревью и объяснение
по M0. Функциональные нарушения доступа/версий/порогов исправляются обязательно. Отсутствие прироста
от реранкера не провал, если эксперимент корректен и вывод предъявлен. Непроверенный случай
помечается «не выполнен», а не засчитывается успехом. Ruff и проверка типов — для кода студента.
