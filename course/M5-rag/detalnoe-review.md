# M5 — риски реализации для отдельного ревью

Выполняется отдельным вызовом по M0. Требования — [задание](zadanie.md), наблюдаемые проверки —
[приёмка](kriterii-priyomki.md). Ревью объясняет риск и указывает место в коде, не вводит новые задачи.

| Пункт | Что искать в реализации и почему |
|---|---|
| M5.1 | Уникальные ключи, транзакции импорта и отчёт отклонённых строк: неполная партия не должна выглядеть полной |
| M5.2 | Разделение успешного парсинга и допуска в индекс; отсутствие default-all и догадок о версии; источник каждой цифры OCR |
| M5.3 | Граница условия/исключения, единицы/цены; ограничения tokenizer не должны молча обрезать факты |
| M5.4 | Замена набора чанков одного источника; отзыв scope при неизменном hash; отсутствие объединения разных прав по тексту |
| M5.5 | Обязательный серверный access_context в запросе до top-k; источник/версия каждого кандидата |
| M5.6 | Одинаковые ограничения обеих веток, дедуп по chunk_id; сравнение при одинаковых данных и параметрах |
| M5.7 | Ограниченный N, возвращаются только разрешённые входные кандидаты; эксперимент без обещания улучшения |
| M5.8 | Валидность ссылок и поддержка утверждений проверены отдельно; conflicting/empty не становятся found=true |
| M5.9 | Сопоставление услуги отделено от извлечения; SQL-ошибка не смешана с not_found; сумма имеет источник и единицы |
| M5.10 | Контакт не выдаёт scope; приватный текст не попадает в технические логи; права одинаковы для всех путей поиска |

Укажите выявленные риски, серьёзность, нарушенное требование и способ проверки исправления.
Отдельно проверьте, что за счёт guardrail не пропала разрешённая работа клиента 7.
