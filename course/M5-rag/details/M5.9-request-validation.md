# M5.9 — Проверка заявки: известное, неизвестное, нарушенное

Требование и интерфейс — [задание](../zadanie.md), пункт M5.9; проверка — [приёмка](../kriterii-priyomki.md).

## Объяснение

Трёхзначная проверка сохраняет различие между отсутствием знания и нарушением. Пустой результат SQL при подтверждённой услуге и ошибка соединения дают разные причины и разные варианты восстановления.

## Разобранный пример

`service=null` → `need_info`; подтверждённое «Устранение течи» в `reference/price.json` имеет active=false → `данных_нет:нет_в_прайсе`. Неопределённый район → уточнение, а известный Колпино с отрицательной SQL-зоной → `правило_не_выполнено:вне_зоны`.

Сначала сохраните доступный вход и происхождение значений, затем промежуточный результат, затем итог. Почему отсутствие телефона не отменяет известное ограничение зоны?

## Частые ошибки

При недоступном справочнике нет отрицательного ответа «услуги нет». Сначала известное нарушение, затем устранимая нехватка, затем неизвестная обязательная проверка. Для вопроса/жалобы/спама проверка полей заявки не запускается. Старый validation eval допустим лишь с проверенным доступным входом и основанием.
