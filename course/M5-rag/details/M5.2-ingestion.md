# M5.2 — Загрузка текста и метаданных

Требование и интерфейс — [задание](../zadanie.md), пункт M5.2; проверка — [приёмка](../kriterii-priyomki.md).

## Объяснение

Ingestion — загрузка и приведение источника к тексту. Успешный парсинг не означает, что документ разрешён для поиска. Сначала фиксируются происхождение и права, затем документ допускается в индекс.

## Разобранный пример

`faq.md` даёт фрагмент «приём заявок ежедневно 9:00–21:00». `fixtures/legacy_formats/api_priema.json` помечен quarantine в manifest фикстур: парсер извлекает текст, но документ не становится публичным.

Сначала сохраните доступный вход и происхождение значений, затем промежуточный результат, затем итог. Что останется доступным после ошибки одного парсера?

## Частые ошибки

OCR — распознавание текста, не диагностика повреждения по фотографии. Сомнительная цифра не служит основанием обещания. Одинаковый текст из разных источников/областей доступа не склеивается с потерей прав.

## Промпт-контракт к ИИ

По циклу M0 укажите scope только M5.2, текущие интерфейсы и миграции. Приложите соответствующий пункт задания и сценарий приёмки; попросите реализовать его без расширения стека и скрытой подмены данных. Проведите отдельный ревью-вызов по [рискам](../detalnoe-review.md), затем проверку и запись понимания.

## Идентичность источника на примере

| source_id | version | content_hash | scope | Значение |
|---|---|---|---|---|
| policy-A | v1 | h1 | all | исходный публичный текст |
| policy-A | v2 | h2 | all | новый текст того же источника; v1 больше не текущий |
| policy-B | v1 | h2 | client:7 | другой источник с тем же текстом; отдельные права |
| policy-A | v2 | h2 | client:9 | изменение прав без изменения текста; публичная выдача отзывается |

Это заданная фикстура. `h1/h2` обозначают рассчитанные хеши, а не фактические хеши файлов.
Повтор строки без изменений не создаёт новых чанков. Одна лишь дедупликация по h2 потеряла бы
границу доступа policy-B. Для первого FAQ-прохода используйте manifest из [cases.md](../cases.md).
