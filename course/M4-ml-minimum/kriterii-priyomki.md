# M4 — Критерии приёмки

Источник требований — [задание](zadanie.md). M0 продолжает действовать. Все сценарии выполняются самостоятельным запуском M4 с клиентом M2; готовые M5/M6 не нужны. Моки проверяют развилку и сбой; качество классификации проверяется только реальными предсказаниями.

M4.2 проверяется внутри A1–A2: совпадают имя и точная revision из задания, сведения manifest, размерность и лимит. У M4.4/M4.5 отдельных критериев и артефактов нет.

## Сдача модуля

Показать рабочий путь: версия базы → три соседа → тип/приоритет → сохранённый результат; затем воспроизвести значимый сбой A6 и объяснить безопасную передачу в M6. Объяснить три вопроса из задания своими словами, пройти отдельное ревью по M0.

Минимальные артефакты в существующем процессе M0: точная команда воспроизведения, manifest модели/данных/разделения, конфиг k/порога/правил, версия промпта и LLM, одна таблица сравнения и вывод сценариев. Для повторного замера LLM сохраняются фактические ответы и расходы: новая генерация может отличаться. Локальный повтор сравнивается с численным допуском. Используйте опубликованный `data/course_pack/eval/classification_test.jsonl` после фиксации решений. Он отделён по семействам, но мал и синтетичен; результаты не доказывают качество реального потока.

Критерий завершения: A1–A8 подтверждены, реальный эксперимент на проверенном пакете выполнен; для A5 используется `data/course_pack/`, диагностика на старом наборе его не заменяет; базовый способ не обязан побеждать большинство или LLM. Применимые проверки кода и типов проходят в рамках M0; новые отдельные отчёты по снятым пунктам не требуются. Полные маршруты «спам → reject без ответа» и «жалоба → оператор» исполняются и принимаются в M6.
