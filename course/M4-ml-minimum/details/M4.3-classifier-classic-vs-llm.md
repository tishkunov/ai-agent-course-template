# M4.3 — Соседи, приоритет и честное сравнение

Контракт и правила — [M4.3 задания](../zadanie.md#m43--локальный-способ-и-сравнение-с-llm), проверки — A3–A5 [приёмки](../kriterii-priyomki.md).

Локальный baseline — простой исходный способ, с которым сравнивается LLM. Он хранит векторы размеченных примеров и голосует по соседям; веса embedding-модели не меняются. Схема без готового приложения:

```text
база = embedding(train.input), train.type, train.id
соседи = top_3(cosine(embedding(вход), база))
тип = победитель голосования, если победитель единственный
согласованность = число голосов победителя / 3
приоритет = явное правило по исходному тексту
если база полноценна, вход не усечён, нет отказа,
   согласованность >= порог и приоритет однозначен:
    принять локально
иначе:
    классификация через M2
```

При `[заявка, заявка, жалоба]` согласованность — `2/3`. Порог `0.8` отправляет этот случай LLM; `2/3` принимает при однозначном приоритете. При `[заявка, заявка, заявка]` число равно 1, но текст может всё равно быть жалобой: соседи отражают представление темы, а не доказательство намерения. Все три могут оказаться нерелевантны — данная эвристика не распознаёт любую неизвестную ситуацию.

Приоритет не голосуется по соседям. В тексте «Искрит сейчас» есть действующая опасность; «Какая гарантия?» — спокойный вопрос. В «вчера искрило, сегодня всё спокойно» важны время и отрицание. Неясность правила вызывает LLM независимо от уверенности типа.

Train даёт соседей и метку большинства; dev позволяет выбрать один порог и промпт; test показывает итог после фиксации. Случайный split строк одного шаблона позволяет запомнить форму фразы. Поэтому manifest описывает семейства и связанные обращения. Старый test содержит 12/81 дословных совпадений с исходным train — таблица на нём диагностическая. Данные не исправляются незаметно во время сравнения.

Accuracy считает правильные ответы среди **всех** примеров; отказы показываются и остаются в знаменателе. F1 для каждого типа показывает сочетание пропусков и ложных срабатываний; рядом нужен support — число примеров этого типа. Ошибки приоритета считаются отдельно. Majority может выиграть из-за дисбаланса — это наблюдение, не повод спрятать результат. В текущем наборе (числа в §0 задания) заявок около 88% test, а жалоба представлена одним примером: такой F1 меняется скачком от одной ошибки и качеством не считается.

Инструкция для LLM-классификации живёт файлом `prompts/classify_v1.md` по правилу M2.3: правка формулировки — это `classify_v2`, а не изменение `v1`, иначе прошлые замеры не с чем сравнивать.

Промпт-контракт по M0: передать авторский manifest split, запросить базу соседей, правило приоритета, проверку split и одну таблицу по заданию; запретить test-примеры в промпте и настройку на test. Мок подходит для проверки числа вызовов, реальная модель — для измерения качества. Ошибка схемы не равна ошибке смысла: валидная метка может оказаться неверной.
