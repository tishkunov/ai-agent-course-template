# M4.6 — Выбор способа классификации

Контракт результата — [M4.6 задания](../zadanie.md#m46--выбор-способа-классификации-и-подключение), проверки — A6–A8 [приёмки](../kriterii-priyomki.md).

Здесь выбирается, кто определяет тип/приоритет: локальные соседи и правило либо LLM. Это не `route_decision`, который появится в M6. Номера S обозначают ответственность; фактически S4 классифицирует до S5 извлечения в ветке заявки.

Пример: соседи дают 2/3 при пороге 0.8 → M2 получает исходный текст с правилами типов/приоритетов → возвращает `{req_type: "жалоба", priority: "средний", reason: "претензия к прошлой работе"}` → приложение проверяет схему и сохраняет метки, `routing_method=llm`, `type_confidence=null`. Численного доверия модель не обещала.

Если M2 вместо метки вернул неизвестный enum, разрешён один повтор формата. Если и он невалиден — оба поля меток становятся `null`, причина `invalid_output`; два фактических вызова учитываются в M2. Если модель явно не смогла различить намерения, причина `ambiguous`, бесконечного повторения нет. Ни локальный кандидат, ни прошлый успешный результат обращения не должны замаскировать отказ текущего прогона.

M6 получает результат с диагностической причиной. Подтверждённый спам ведёт к reject без ответа, жалоба — к оператору; неподтверждённый результат также требует оператора. Сам M4 проверяется spy-потребителем и не реализует эти действия. Статус и side effects принадлежат последующим компонентам.

Для продолжения M6 передаёт `classification_text` по contracts §8: просьба/исправления,
последний вопрос, последняя реплика. «Учебная 10» после вопроса об адресе остаётся заявкой;
«Лучше скажите, какая гарантия?» меняет ветку. Старый req_type не является входным эталоном.

Больший порог означает **больше** LLM-вызовов: условие локального принятия становится строже. Проверять влияние на dev, до test. Число вызовов не обязано уменьшиться на любом наборе, а согласованность типа не позволяет пропустить неоднозначность приоритета.

Промпт-контракт по M0: передать контракт задания, границы M4/M6 и сценарии отказа; запросить адаптер сохранения и изолированные проверки с M2 spy. Не разрешать менять статус обращения или отправлять уточнение из классификатора.
