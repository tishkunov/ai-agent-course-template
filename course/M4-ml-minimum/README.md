# M4 — Прикладная классификация

Определяем тип обращения по ближайшим размеченным примерам, приоритет — явным правилом. Неоднозначные случаи передаём LLM через M2. Сравниваем ошибки, время и расходы на одинаковом входе; гарантированной доли локальных решений нет.

Опора: M1 (сохранённые обращения), M2 (клиент и расходы). Результат классификации использует M6, модель эмбеддингов — M5. Сквозные правила — [contracts.md](../contracts.md).

| Порядок | Работа | Пояснение |
|---|---|---|
| M4.1 | Векторы, cosine, ближайшие примеры | [Эмбеддинги](details/M4.1-embeddings-cosine.md) |
| Внутри M4.1 | Одна фиксированная модель; прежнее сравнение M4.2 снято | [Модель и версия](details/M4.2-embedding-model-choice.md) |
| M4.3 | Голосование, правило приоритета, train/dev/test и сравнение с LLM | [Классификация](details/M4.3-classifier-classic-vs-llm.md) |
| M4.6 | Локальное решение → LLM → контролируемый результат для M6 | [Подключение](details/M4.6-routing.md) |

Старые номера [M4.4](details/M4.4-clustering.md) и [M4.5](details/M4.5-regression-overview.md) остаются указателями. Кластеризация и регрессия не требуют кода, отчётов или отдельной сдачи.
