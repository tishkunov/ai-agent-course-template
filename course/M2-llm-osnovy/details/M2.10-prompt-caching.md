# M2.10 — Prompt caching

## Что это и зачем

Промпт извлечения состоит из большой стабильной части (инструкция + few-shot, одинаковая на каждом вызове) и маленькой переменной (текст обращения). Prompt caching провайдера позволяет не платить полную цену за стабильную часть на каждом вызове — она кешируется на стороне провайдера.

## Теория простым языком

**Prompt caching ≠ кеш ответов.** Кешируется *префикс промпта* (вход), а не результат. Модель всё равно генерирует ответ каждый раз — просто обработка неизменного начала промпта стоит дешевле (если условия и тариф выбранного провайдера предусматривают скидку). Кеш готовых ответов на одинаковый вопрос — это M8, другая механика.

**Порядок имеет значение.** Кешируется именно *префикс*: всё до первого различия. Поэтому промпт строят как «сначала всё стабильное (system + few-shot), потом переменное (текст обращения)». Если засунуть текст обращения в середину, кешируемого префикса почти не остаётся.

**Инвалидация естественная.** Поменял промпт → завёл `extract_v2` → префикс другой → старый кеш просто не используется. Ничего чистить руками не надо.

**Не все провайдеры умеют.** Поддержку и условия проверяют для выбранного адаптера и версии провайдера. Код должен работать и без него — просто без экономии, без ошибок.

## Что сделать по шагам

1. Собрать `messages` так, чтобы стабильная часть (system + few-shot) шла строго перед переменной (текст обращения).
2. Если выбранный провайдер поддерживает prompt caching, настроить его по документации этого провайдера. Совпадения префикса недостаточно для гарантии попадания: действуют ограничения длины, времени и реализации.
3. Пробросить `cache_hit` в `LLMResult`, если провайдер отдаёт признак попадания.
4. Провайдер без prompt caching → тот же код работает без него.
5. Два одинаковых вызова: записать наблюдаемый usage и `cache_hit`. Нет подтверждённого попадания — это допустимо; если провайдер не сообщает признак, `cache_hit=None`, а не выдуманный `True`.

## Промпт-контракт к ИИ

Скоуп — только M2.10. Дать: структуру промпта (стабильное → переменное), что кешируется префикс, не ответ, что адаптер без поддержки работает без кеша. Запросить: разделение промпта на префикс/переменную часть, включение caching у провайдера, проброс `cache_hit`. Запретить: кешировать ответы (это M8), ломать работу на провайдере без caching.

## Частые ошибки

- Текст обращения оказался в начале/середине промпта — кешировать нечего.
- Путают prompt caching и кеш ответов, реализуют не то.
- Код падает на провайдере без кеша префикса, потому что жёстко ждёт полей кеша в ответе.

## Готово, когда

См. `kriterii-priyomki.md` § M2.10. Коротко: стабильный префикс отделён; использование кеша подтверждается только данными провайдера, `cache_hit` отражается в результате, на провайдере без кеша всё работает.
