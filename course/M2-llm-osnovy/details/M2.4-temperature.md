# M2.4 — Температура и детерминизм

## Что это и зачем

Извлечение полей — задача с одним правильным ответом: адрес в тексте либо есть, либо нет. Здесь не нужна «креативность» модели, нужна воспроизводимость: низкая вариативность при одинаковом входе. Температура 0 уменьшает вариативность, но не гарантирует повторение ответа.

## Теория простым языком

**Температура** — насколько модель «рискует» при выборе следующего токена. При 0 она почти всегда берёт самый вероятный вариант → ответы стабильны и предсказуемы. При 0.7–1.0 подмешивается случайность → ответы разнообразнее, но на одном входе будут разными.

- **низкая (≈0):** извлечение, классификация, структурированные ответы, всё, что потом проверяется по эталону;
- **высокая:** генерация текста, где нужна вариативность (в этом проекте почти нигде).

«Почти» детерминизм: даже при температуре 0 полная воспроизводимость не гарантирована (влияет железо провайдера, версия модели). Размер разброса наблюдают в своём прогоне; гарантии минимума нет.

**Из конфига, не по месту.** Значение температуры для шага извлечения задаётся рядом с промптом (в конфиге промпта или `Settings`), а не числом в коде вызова — чтобы было одно место, где видно все параметры шага.

## Что сделать по шагам

1. Параметр `temperature` для шага извлечения — в конфиге промпта/`Settings`, значение ≈ 0.
2. Все параметры вызова (`temperature`, `max_tokens`, `model`) задаются явно при формировании запроса, не остаются на дефолтах SDK.
3. Тест: два одинаковых вызова extract (LLM замокан детерминированно — тут проверяется, что код не подмешивает случайность и передаёт `temperature=0`).

## Промпт-контракт к ИИ

Скоуп — только M2.4. Дать: требование `temperature ≈ 0` для извлечения из конфига. Запросить: вынос параметра в конфиг, явную передачу всех параметров вызова. Запретить: хардкод температуры в коде вызова, высокую температуру для извлечения.

## Частые ошибки

- Температура не задана вовсе — используется дефолт провайдера (часто ~0.7).
- Значение зашито числом в трёх разных местах.
- «Поставим 0.3, вдруг лучше» без прогона — это уже порог, его выбор оформляется по M0.4.

## Готово, когда

См. `kriterii-priyomki.md` § M2.4. Коротко: извлечение идёт с `temperature ≈ 0` из конфига, мок подтверждает передачу параметров, а вариативность реальной модели записана в отчёте.
