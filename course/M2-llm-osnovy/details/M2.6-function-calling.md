# M2.6 — Function calling / tool use (основы)

## Что это и зачем

В M6 агент будет вызывать инструменты: «проверь зону по адресу», «создай заявку», «отправь ответ». Механизм, которым модель просит вызвать функцию, называется function calling (tool use). В M2 его трогают на уровне «понять, как устроено»: модель предлагает вызов с аргументами, система его *не выполняет* (заглушка), но аргументы проверяются схемой.

## Теория простым языком

**Модель не выполняет функции.** Она возвращает «хочу вызвать `check_zone` с аргументами `{"address": "Ленина 5"}`». Выполняет — твой код. Он решает: вызвать по-настоящему, отклонить, спросить подтверждение. Это разделение — основа безопасности агента в M6.

**Схема аргументов = контракт.** Инструмент описывается именем и JSON-схемой аргументов. Модель обязана прислать аргументы по этой схеме; несоответствие — отклоняется до всякого выполнения.

**Structured output vs tool call — в чём разница:**
- structured output: «верни ответ в этой форме» — один ожидаемый результат, всегда по схеме;
- tool call: «выбери инструмент из набора и дай аргументы» — модель может выбрать один из нескольких инструментов, может не выбрать ни одного (и это нормально, не ошибка).

## Что сделать по шагам

1. Описать один демонстрационный инструмент: имя + pydantic-схема аргументов (например `echo(text: str)` или `get_time(city: str)`).
2. Вызов `client.complete(messages, tools=[...])`; из результата достать предложенный `{tool, args}`.
3. Валидировать `args` схемой инструмента. В M2 выполнение — заглушка: вернуть эхо аргументов, ничего в мире не менять.
4. Обработать «модель не вызвала инструмент» — вернуть это как валидный исход, не как ошибку.
5. Короткая заметка (в коде или `docs/`) — чем tool call отличается от structured output.
6. Тесты: валидные аргументы → приняты; кривые → отклонены по схеме; нет вызова → обработано.

## Промпт-контракт к ИИ

Скоуп — только M2.6. Дать: что действие НЕ выполняется (заглушка), что аргументы валидируются схемой. Запросить: описание инструментов, разбор ответа с tool-call, валидацию аргументов, заметку про отличие от structured output. Запретить: выполнять реальные побочные действия, реализовывать реестр инструментов с правами (это M6.2).

## Частые ошибки

- Код пытается «выполнить» то, что предложила модель, по-настоящему — в M2 этого быть не должно.
- «Модель не вызвала инструмент» трактуется как ошибка.
- Аргументы берутся как есть, без проверки схемой.

## Готово, когда

См. `kriterii-priyomki.md` § M2.6. Коротко: tool-call демонстрируется, аргументы валидируются схемой, отсутствие вызова обработано, отличие от structured output описано.
