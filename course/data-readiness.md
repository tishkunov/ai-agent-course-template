# Данные для обязательной приёмки

Этот файл разделяет подготовку учебного комплекта и работу студента. Бизнес-правила остаются в
[contracts.md](contracts.md); форматы учебного пакета — в [SCHEMA](../data/SCHEMA.md).

## Кто готовит данные

Автор курса поставляет проверенные входы, ожидаемые результаты с основаниями, общие
train/dev/test по семействам и фиксированные справочники/версии документов. В обязательных
сценариях автор задаёт также доверенную идентичность, часы, ответы/сбои внешних зависимостей.
Студент подключает эти данные к своей реализации, пишет тесты и объясняет результат.

Студент не обязан чинить весь исторический корпус, придумывать бизнес-эталоны или независимо
переразбивать его для сдачи. Обнаруженную ошибку он фиксирует с case_id и основанием; спорный
gold не становится правильным лишь потому, что лежит в файле. Изменения gold выпускает автор
отдельной версией, без подгонки под ответ модели.

## Что доступно сейчас

Выпущен [course-pack-1](../data/course_pack/README.md): 498 сценариев с входами,
эталонами и основаниями. Проверка согласованности, хешей, splits и тесты валидатора проходят.
Независимое человеческое review отмечено как pending; качество будущей реализации студента
проверяется отдельным запуском. Сборка данных не означает пройденный quality gate приложения.

| Модуль | Задачи в пакете / файлы |
|---|---|
| M1 | `inputs/end_to_end.jsonl`: адаптировать разрешённые поля обращения к API |
| M2 | `extraction` (80), `accounting`; модели передавать только `input.text` |
| M3 | `dialogs` (24): события, начальное состояние, часы и ожидаемые состояния |
| M4 | `classification` (160), `routing` (30); готовые train/dev/test в `eval/` |
| M5 | `kb/manifest.json`, `rag` (40), `validation` (30), `fixtures/` |
| M6 | `end_to_end` (12), `core` (12 дополнительных), `routing`, `faults` |
| M7 | `security` (24 пары атака/полезный запрос), `judge` (6), `gate`, `coverage.json` |
| M8 | `replay` (100 доставок, 80 уникальных событий), `cache` (40), `faults` |
| M9 | `telemetry`, `accounting`, `faults`; реальная трасса получается при запуске приложения |

Загрузка: `load_course_inputs(task, split=...)` из `data.loader` возвращает входные конверты;
`load_course_cases` возвращает полный эталон для проверяющего. Case ID, family, split,
фикстуры зависимостей и ожидаемые результаты в промпт не включают. Для событийных задач
тестовый адаптер воспроизводит события и сравнивает состояния/эффекты своей реализации.
Готового исполнения приложения в данных нет.

Test нового пакета используют после фиксации решений; regression доступен при разработке.
Публикация test рядом с курсом не делает его закрытым экзаменационным набором.

## Что получает студент в готовом пакете

| Часть | Содержимое |
|---|---|
| Manifest | Версия набора и правил, хеши, список обязательных case_id и состав splits |
| Входы | Текст/история и только разрешённые метаданные; отдельно тестовая серверная идентичность |
| Эталоны | Ожидания, допустимая нормализация и доказательства из входа/источников |
| Справочники и KB | Фиксированные записи, scope, версии, периоды действия и специально заданные дефекты |
| Сценарии | Упорядоченные события, управляемые часы/сбои, состояние и эффекты после каждого события |

Один family_id объединяет варианты ситуации и её проекции M2–M7; split общий для всего курса.
Модель получает только доступный вход. Эталоны, теги генератора и case_id в промпт не попадают.
Мок проверяет код; live-прогон — модель; журнал БД — эффект. Эти результаты не заменяют друг друга.
