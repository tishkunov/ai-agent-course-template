# M1.4 — FastAPI: приложение и эндпоинты

## Что это и зачем

Это HTTP-слой: точка, где сеть встречается с твоим кодом. Его задача — разобрать запрос, проверить вход по схеме, вызвать нужный сервис, превратить результат (или ошибку) в HTTP-ответ. Вся доменная логика — глубже, в `services/`. Если логика заползает в роуты, её нельзя переиспользовать (в M6 те же шаги дёргает граф агента, а не HTTP) и тяжело тестировать.

## Теория простым языком

**App factory** — функция `create_app()`, которая собирает приложение: создаёт `FastAPI()`, подключает роутеры, middleware, обработчики ошибок, и возвращает его. Зачем функция, а не глобальный объект: в тестах можно собрать приложение с тестовым конфигом, не трогая рабочий.

**`Depends` (dependency injection)** — способ сказать «этому хендлеру нужна сессия БД / проверенный API-ключ / настройки». FastAPI сам вызовет зависимость, передаст результат аргументом, а после ответа — приберёт (закроет сессию). Пример: `async def get_request(id: str, session = Depends(get_session), _ = Depends(require_operator))`.

**Middleware** — код, который оборачивает каждый запрос. Нам нужен один: сгенерировать `request_id` (или взять из заголовка) и положить его в контекст, чтобы все логи одного запроса были связаны.

**Единый обработчик ошибок** — вместо `try/except` в каждом роуте регистрируется один обработчик на тип доменной ошибки. Сервис бросает `NotFoundError` → обработчик превращает в `404 {error, detail}`. Роут остаётся чистым.

**`response_model`** — указываешь схему ответа, FastAPI валидирует и фильтрует выход по ней. Гарантия, что наружу не уедет лишнее поле из ORM-объекта.

## Что сделать по шагам

1. Проследить готовую `create_app()` в `app/main.py`: подключение роутеров, middleware `request_id`, обработчиков ошибок.
2. Прочитать зависимости в `api/deps.py` и `core/security.py`: JWT уже реализован, но полномочие оператора предстоит проверить в M1.8.
3. Обработчики исключений: доменные ошибки → коды по §0 (валидация 422, не найдено 404, конфликт 409, аутентификация 401, недостаточные полномочия 403; добавить недостающую доменную ошибку 403). Тело — `{error, detail}`. Необработанное → 500 без стек-трейса наружу.
4. Роутеры:
   - `POST /requests` → `RequestCreate` на входе, `RequestOut` в `response_model`, защита `require_api_key`;
   - `GET /requests/{id}` → `RequestOut`, защита `require_operator`;
   - `GET /health` → `HealthOut`.
5. Проверить, что `/docs` открывается и показывает все три эндпоинта.

## Промпт-контракт к ИИ

Скоуп — только M1.4. Дать: контракты кодов ответов, список зависимостей, правила маппинга ошибок из §0. Запросить: разбор готового HTTP-слоя и добавление доменной ошибки 403. Запретить: доступ к БД прямо в роуте, `try/except` в каждом роуте вместо общего обработчика, переписывать готовую проверку JWT (её полномочие дорабатывается в M1.8).

## Частые ошибки

- Роут сам открывает сессию и пишет SQL.
- В каждом роуте свой `try/except` — обработка ошибок расползается и расходится.
- Стек-трейс уходит клиенту в теле 500.
- Нет `response_model` — наружу протекают поля ORM-объекта.
- `create_app` как глобальный `app = FastAPI()` на уровне модуля — тесты не могут подменить конфиг.
