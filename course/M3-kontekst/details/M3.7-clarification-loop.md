# M3.7 — Один вопрос и сохранённая пауза

Здесь объединяются история, извлечение M2, корреляция и отправка. Вход считается заявкой по условию упражнения; определять её тип до M4 не требуется. Список причин включает недостающие поля и конфликты. В M6 его дополнят результаты проверок условий.

При R=0 и отсутствии адреса зарегистрируйте q1 → R=1, `need_info`, завершите обработку. Новый event id с адресом возобновляет обращение → переизвлечение → `in_progress`. Статус означает готовность к следующему шагу, а не исполнение бизнес-действия.

При MAX=2 ответ «Спасибо» на q1 оставляет причину. Зарегистрирован q2 → R=2. Следующее «Спасибо» → `escalated/limit`, без q3. Но полный адрес в ответ на q2 принимается: лимит ограничивает число вопросов. Повтор доставки «Спасибо» с прежним event id не считается новым ответом и не расходует ещё один круг.

Для молчания используйте сохранённое время зарегистрированного вопроса. Тест переводит часы к границе таймаута и вызывает sweep; ждать сутки не нужно. `updated_at` непригоден как единственный таймер: техническое обновление может сдвинуть его без нового вопроса. Sweep и ответ должны повторно проверять состояние под сериализацией, чтобы старое решение таймаута не перезаписало уже принятый ответ.

При смене сути, нескольких заказах, отмене/переносе обязательный исход — оператор, причина `scope_change`. Это не классификация всего потока и не автоматическое разбиение. Все ветви возвращают управление; ожидание клиента не реализуется циклом while.
