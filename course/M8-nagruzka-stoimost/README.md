# M8 — Нагрузка и стоимость

Устойчивость под нагрузкой и контроль стоимости: очередь + воркер (быстрый приём, обработка отдельно), таймаут/retry/circuit breaker на внешних вызовах, graceful degradation, LLM-fallback на запасную модель, кеш на знаниях (не на решениях), бюджеты и роутинг моделей по сложности.

Стоит на: M1–M6. Сквозные механизмы поверх пайплайна S1–S10 (см. `course/README.md` → «Сквозные механизмы»): надёжность и стоимость. Нагрузка на ноуте — функциональная проверка механизмов.

## Порядок работы

M8.1 Redis Streams и один worker → M8.2 повтор доставки/сохранённая пауза → M8.3 ограниченные
сбои → M8.4 безопасные исходы и M8.5 запасной адаптер → M8.6 кеш знаний с правами →
M8.7 бюджет каждой фактической попытки → M8.8 небольшой локальный поток с моками.

Приём и граф уже соединены runner-ом M6; M8 заменяет явный запуск доставкой через очередь.
Каждый шаг расширяет уже созданный компонент; оба реальных адаптера нужны в M8, но не были
обязательны в M2. Событие очереди имеет event_id и request_id; ack завершает событие, включая
need_info/escalated. Ограничение между записью БД и публикацией объяснено в задании; обязательных
outbox/нового брокера нет. Сквозной источник — [contracts.md](../contracts.md).
