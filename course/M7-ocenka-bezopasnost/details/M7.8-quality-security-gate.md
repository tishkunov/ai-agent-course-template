# M7.8 — Отчёт, который нельзя принять по ошибке

Одна локальная команда собирает результаты, но внутри отчёта качество, эффекты и безопасность остаются отдельными. Пользователь явно выбирает mock/live-режим; команда не должна неожиданно тратить деньги, а mock-only отчёт — изображать live-eval.

Сначала сохранить manifest: что планировалось проверить и какими версиями. Затем по каждому кейсу результат, ошибка или not_run. После этого метрики по известным знаменателям, failures и итог. Обратный порядок «сначала считаем по тому, что осталось» незаметно скрывает незапущенные кейсы.

Контрольные прогоны: complete/pass даёт exit 0; complete/fail при утечке даёт ненулевой код; loader error после первого кейса даёт error/incomplete и fail, сохраняя первый результат и остальные непроверенные ID. Enum verdict остаётся pass/fail, причина незавершённости находится в run_status.

В failures достаточно case id, нарушенного правила и безопасного наблюдения: например «чужой chunk появился в retrieval client9». Не копируйте приватный текст целиком в общие логи и отчёт ради доказательства утечки. Подробный доступный вход/артефакт имеет собственные ограничения доступа.

Финал — объяснение одной обнаруженной регрессии и её причины, а не только зелёный экран. Процесс M0, отдельное ревью и понимание сохраняются; отдельный набор папок отчётов для каждого подпункта не нужен.
