# M9 — Детальное ревью

Требования — в задании, воспроизводимые сценарии — в приёмке. Этот документ ищет риски
реализации и не вводит новых задач. Прогоняй отдельным вызовом критика по M0.

## M9.1 — Trace

Проверь, что run и request не отождествлены. Повтор экспорта call_id не увеличивает стоимость. Расход одного run сравнивается с тем же run; полная стоимость request — по всем run. Экспорт не раскрывает raw-контекст и не блокирует обработку неограниченным буфером/timeout. При потере span trace честно неполон.

## M9.2 — Логи

Контекст worker должен очищаться после события; особенно проверь исключения. Запрет PII охватывает exception payload и произвольные поля, а не только msg. Ошибка sink не порождает рекурсивный лог и бизнес-исключение. HTTP X-Request-ID и доменный ID различены.

## M9.3 — Метрики

Ищи labels с IDs/свободным текстом и путаницу секунд/миллисекунд. Error rate — попытки к попыткам, hit rate — hit к lookup. Паузы и downtime не являются активным временем. No-data не заменён нулём; транспортный pending не выдан за число уникальных событий.

## M9.4 — Формулы

Состояние done не стирает историю оператора. Когорта/снимок/календарный расход имеют разные области; JOIN с actions/escalations может умножить llm_calls. Проверь distinct call_id и уникальные обращения, пустой знаменатель n/a и признаки unknown/estimated.

## M9.5 — Панели

Каждой линии соответствует понятное действие и подписанное окно. Конфиг воспроизводим, секретов в экспорте нет. Панели не требуют просмотра чужих raw-текстов ради перехода к trace. Не сравнивай разные когорты без подписи.

## M9.6 — Алерты

Порог без окна/минимального знаменателя создаёт шум. Группировка не должна скрывать восстановление; тесту нужен resolved, а не только firing. При сбое наблюдения возможна потеря alert, это не маскируется обещанием надёжной доставки. Реальных получателей нет.
