# M9.3 — Агрегаты работы системы

## Что это и зачем

Counter считает события, gauge показывает текущее состояние, histogram собирает распределение.
Для latency важны границы: HTTP-приём, активная работа run и ожидание в очереди — разные интервалы.
Время до следующего сообщения клиента не является latency LLM или worker.

## Разобранный пример

У A одна успешная попытка; у B две неудачные: внешняя error rate = 2/3 по этому окну.
Это не значит, что 2/3 обращений завершились ошибкой. Cache hit rate имеет другой знаменатель:
только lookup этого кеша. P95 малой выборки не доказывает устойчивость под нагрузкой.

## Что сделать по шагам

1. Экспортируй метрики задания в Prometheus; подпиши секунды и определение каждого счётчика.
2. Ограничь labels значениями step/model/outcome, IDs оставь в логах/trace.
3. Проверь изменения A/B и снимок backlog по M8.
4. Отключи scrape/export: обработка продолжается, отсутствие наблюдений не подменяется нулями.

## Промпт-контракт к ИИ

Дай имена/типы метрик, окна и знаменатели. Попроси экспорт существующих событий; не добавляй request_id-label или второй источник цены.

## Риски и проверка

Ожидание человека попало в рабочую latency; histogram заменён средним; Redis entries посчитаны уникальными событиями; пропавший scrape трактуется как отсутствие ошибок.

Поведение задаётся в [задании](../zadanie.md), точная проверка — в соответствующем пункте
[приёмки](../kriterii-priyomki.md). После кода нужен отдельный вызов ревью по M0.
