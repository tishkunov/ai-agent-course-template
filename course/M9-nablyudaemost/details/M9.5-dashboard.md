# M9.5 — Одна панель с проверенными числами

## Что это и зачем

Дашборд строится после данных. Prometheus показывает технические наблюдения, PostgreSQL —
бизнес-результаты и расходы. Два блока используют явные окна и единицы; расхождение между ними
может быть объяснимо разными периодами, но это должно быть видно читателю.

## Разобранный пример

После A виден успешный run; после B — timeout-попытки и эскалация. Выбери одинаковое окно,
покажи знаменатель доли и найди B в trace. При отключении exporter панель показывает отсутствие
свежих данных, не «всё хорошо, ошибок 0».

## Что сделать по шагам

1. Подключи существующие Prometheus и PostgreSQL к Grafana, собери блоки из M9.5 задания.
2. Подпиши окно/когорту, секунды, валюту, знаменатели и число неизвестных расходов.
3. Сохрани dashboard JSON и конфигурацию без секретов; проверь импорт.
4. Разбери A/B и снимок бизнес-фикстуры, не добавляя новых сервисов наблюдения.

## Промпт-контракт к ИИ

Попроси один экспортируемый dashboard с двумя блоками и подписанными формулами. Передай данные A/B; запрети пустые панели, raw-контекст и секреты в конфиге.

## Риски и проверка

Красивый график без данных; неподписанный знаменатель; dashboard существует только в UI; пропуски экспорта закрашены зелёным нулём.

Поведение задаётся в [задании](../zadanie.md), точная проверка — в соответствующем пункте
[приёмки](../kriterii-priyomki.md). После кода нужен отдельный вызов ревью по M0.
