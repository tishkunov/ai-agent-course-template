# M0.6 — Ведение решений и промптов

## Зачем это

Через месяц ты не вспомнишь, почему `MAX_CLARIFY_ROUNDS = 3`, а не 5, и какой версией промпта извлечения пользовался в M2. `docs/decisions.md` и `prompts/` — это внешняя память проекта. Их заводят в M0, а не «когда понадобится» в M3: если начать вести историю с середины, у ранних решений истории уже не будет, а регресс-тесты промптов в M7.5 опираются именно на неё.

## Как на практике

**`docs/decisions.md`** — формат ADR, одна запись = одно решение:

```
## 2026-09-09 · M0.5 · Стек для /ping
Решение: голый http.server, без FastAPI.
Альтернативы: FastAPI (ближе к боевому, но лишний вес для тренировки).
Причина: цель пункта — процесс, не стек.
```

Запись — это выжимка «решение + альтернативы + причина», НЕ лог чата. Сюда же попадают: выбор числовых порогов (M0.4), изменения зафиксированных контрактов, «известные ограничения» (M0.7), пометки `OVERRIDE:`.

**`prompts/`** — конвенция `<step>_v<N>.md`:

```
prompts/
  ping_v1.md          тренировочный промпт-контракт из M0.5
  extract_v1.md        M2
  clarify_v1.md        M3
  summarize_v1.md      M3
  rag_answer_v1.md     M5
  judge_v1.md          M7
```

Промпт не подошёл по формату ответа → заводишь `extract_v2.md`, а не правишь `v1` молча. Старые версии остаются — на них держится регресс.

Оба каталога — в git с первого коммита.

## Частые ошибки

- `decisions.md` превращается в лог диалога с ИИ.
- Промпт правится на месте, версии не растут — история потеряна.
- Каталоги заведены, но пустые: первой записи из M0.5 нет.
- `prompts/` заводят только в M2, когда появился первый «боевой» промпт.

## Готово, когда

`docs/decisions.md` и `prompts/` в git, содержат первую запись/файл из M0.5. См. `kriterii-priyomki.md` § M0.6.
