# M6.3 — Тот же check_zone через MCP

Требования — [M6.3 задания](../zadanie.md), проверка — T16. Меняется транспорт одного инструмента, доменный смысл остаётся прежним.

При прямом вызове диспетчер после проверок вызывает Python-адаптер. При MCP он обращается к локальному серверу по stdio, получает протокольный результат и нормализует его в ту же оболочку status/data/source_refs/reason. Полезно сравнивать эти две трассы на одинаковом district и контексте доступа.

Сервер публикует только check_zone; команда запуска и окружение задаются доверенной конфигурацией приложения. Аргументы модели не являются командной строкой, SQL или настройкой сервера. Клиентский allowlist остаётся, сервер также проверяет схему и допустимость операции. Read-only описание инструмента само по себе не заменяет исполнение этих ограничений.

При остановленном сервере результат unavailable, а не active=false. При запрещённом чтении direct и MCP одинаково отказывают. В этой задаче не нужны удалённый каталог MCP, браузер, произвольное подключение серверов или отдельный агент на сервере.

При реализации зафиксировать версии SDK/протокола и выполнить реальный локальный roundtrip по [официальному руководству MCP](https://modelcontextprotocol.io/docs/2026-07-28/develop/build-server). В stdio stdout занят протоколом; диагностический вывод направляется отдельно. Документация проверена при редактуре, библиотека не установлена за студента.
