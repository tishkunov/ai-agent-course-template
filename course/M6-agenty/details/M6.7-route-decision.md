# M6.7 — Решение по основаниям

Источник правил — [contracts.md §7](../../contracts.md#7-таблица-приоритетов-маршрута-c06), реализация — [задание](../zadanie.md), проверки — T15 и ветки T02–T05.

Для каждого правила сначала проверяется применимость, затем триггер. Зона/прайс относятся к заявке с подтверждёнными исходными фактами; вопрос о гарантии не должен провалить проверку адреса. Спам и жалоба получают свои ветки раньше полей заявки.

Известная зона=no и отсутствующий контакт → оператор по зоне. Район неизвестен → уточнение причины, а не выдуманная зона=no. При amount=15000 и прочих допустимых условиях возможен авто, при 15001 — оператор. Число из текста и скрытая сумма эталона не являются подтверждённой стоимостью.

LLM M4 не выдаёт сопоставимую численную probability: type_confidence=null нормально при проверенных непустых метках. Отсутствующая метка означает неподтверждённость. У RAG основание — доступный источник и found, а не общий confidence всего обращения.

В route_reason сохраняется первое применимое сработавшее правило; остальные основания остаются в checks/validation для оператора. Решение авто ещё не done: только журнал подтверждённых необходимых действий завершает обращение.

Промпт-контракт M0 должен ссылаться на общий контракт, а не на прежний порядок синтетической разметки. Модель не реализует decide_route своим свободным ответом.
