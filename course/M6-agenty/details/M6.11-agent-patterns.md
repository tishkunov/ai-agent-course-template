# M6.11 — Объяснить границу автономности

Требование — [M6.11 задания](../zadanie.md). Отдельных reflection-циклов или мультиагентной реализации нет.

Сравните два варианта на своей трассе. В построенном графе модель выбирает порядок разрешённых чтений, код требует основания и допускает эффект. В свободном планировании модель предлагает весь план: «создать заявку, затем уточнить цену». Для проекта второй порядок недопустим: эффект должен следовать проверкам.

Объясните по trace, какой выбор вы оставили модели и где остановили ошибочную последовательность. Самопроверка модели могла бы снова уверенно повторить ошибку; она не заменяет детерминированное разрешение. Несколько агентов также не создают отсутствующее право.

Сдаётся короткое объяснение в записи M0 с указанием конкретного разрешённого и запрещённого перехода, не каталог названий паттернов.

Также сравните T01 с обычным кодом `check_zone → check_price`: проверки те же, LLM для выбора
порядка не нужен. В учебной T01 три таких вызова; назовите фактическое число в своей трассе.
Если модель не собрала обязательное основание, обращение уйдёт оператору. Поэтому упражнение
показывает механизм и цену автономности, а не доказывает преимущество агента над простым кодом.
Реализовывать вторую систему для этого объяснения не требуется.
