# M6.4 — State хранит основания

Полный состав — [M6.4 задания](../zadanie.md), проверки — T12–T14.

У обращения есть история, текущие факты и круги уточнений; у прогона — event_id, run_id, текущий шаг и счётчики. Новая реплика создаёт новый прогон в прежнем обращении. Recovery использует старый run_id; иначе обнуление лимитов позволит бесконечно повторять незавершённый цикл.

Checks зависят от фактов. В версии 1 адрес был в Приморском районе и зона=yes. Оператор записал другой район в версии 2: прежняя зона теперь не относится к актуальному адресу. Недостаточно сохранить рядом старый yes и новый адрес — узел маршрута должен видеть несовпадение версий и повторить проверку.

История остаётся в messages; State хранит ссылку и нужный ограниченный контекст M3. Краткий summary — производные данные, он не может отменить новое явное исправление. В State нет объекта SDK, DB session или секрета. Проверка сериализации нужна вместе с проверкой смысла восстановления: JSON может успешно сохранить устаревшее разрешение.

Промпт-контракт M0: перечислить группы State из задания, указать владельцев данных M2–M5, попросить round-trip и пример инвалидации адреса. Не вводить одну универсальную confidence для всех шагов.
