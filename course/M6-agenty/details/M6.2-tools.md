# M6.2 — От предложения к наблюдению

Схемы, лимиты и права задаёт [M6.2 задания](../zadanie.md); проверяют T01/T06–T08/T16 [приёмки](../kriterii-priyomki.md).

Tool call — структурированное предложение, а не выполненная функция. Клиент M2 возвращает `{tool,args}`. Диспетчер сравнивает имя с реестром чтений, валидирует аргументы и доступ, проверяет связь аргументов с фактами обращения, затем вызывает адаптер M5. Он возвращает наблюдение модели следующего хода.

Пример: check_price по подтверждённому SRV-1007 возвращает price=2500 и unit=услуга. При quantity=1 есть основание amount=2500. Если количество неизвестно, у инструмента нет права угадать его ради заполнения результата. Аналогично неизвестный район не означает запрет зоны.

В оболочке инструмента `not_found` и `unavailable` различны: первое означает завершённый поиск без записи, второе — чтение не удалось. `denied` не раскрывает содержимое приватного документа. Схема результата проверяется так же, как схема аргументов; произвольный текст из источника не меняет системные правила.

Цикл ограничен числом предложений и фактических LLM-вызовов. При повторе той же пары имя/args без новых фактов нет прогресса: прекращаем, сохраняем причину, передаём оператору. Предложение нескольких вызовов за ход в учебном варианте отвергается до исполнения. Нельзя незаметно выполнить «первый безопасный», потеряв второй запрещённый.

Промпт-контракт M0: реестр только чтений, схемы из задания, один вызов за ход, лимиты и наблюдаемые запреты. Не просить готовую скрытую цепочку рассуждений или исполнение инструментов внутри LLMClient.
