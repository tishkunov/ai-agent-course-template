# M6.1 — Модель внутри управляемого процесса

Контракт — [задание](../zadanie.md), пример — [успешная и ошибочная трассы](../scenarios.md), приёмка — T01/T06.

В обычном workflow код заранее назначает следующий шаг. В нашем узле модель сама предлагает, какое разрешённое чтение выполнить и с какими аргументами, получает наблюдение и может сделать следующий вызов. Это ограниченная агентная часть внутри фиксированного бизнес-процесса.

На заявке о замене смесителя модель может сначала запросить цену, потом зону, либо наоборот. Код в обоих случаях потребует актуальные основания и допустимую сумму до ticket. Модель не получает create_ticket среди инструментов чтения. Оператор разбирает неопределённость, но его подтверждение тоже проходит права и правила.

Трасса показывает только предложенные вызовы, наблюдения и короткие основания. Скрытый ход рассуждений не нужен для проверки того, кто разрешил эффект. Если в trace нет шага проверки, красивое объяснение модели не восполняет его.

В промпт-контракт M0 передать эту границу и безопасную фикстуру, попросить отдельно показать решение модели и проверку кода. Частая ошибка — назвать произвольную цепочку функций автономным агентом или разрешить модели выбирать бизнес-маршрут вместо кода.
