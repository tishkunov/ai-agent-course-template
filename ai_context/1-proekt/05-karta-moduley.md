# Карта модулей M0–M9

### 2.4 Карта модулей (технологии → задача → результат)

| M | Название | Технологии/понятия | Задача | Результат |
|---|---|---|---|---|
| M0 | Старт | работа с ИИ, промпт-контракты, критерии приёмки | настроить процесс работы с ИИ | рабочий цикл, пройден на игрушечном примере |
| M1 | Бэкенд-фундамент | async/await, FastAPI, pydantic, Postgres+ORM, Alembic, Docker, JWT, Redis(conn) | проверить и дополнить существующий каркас | API в Docker с healthcheck и миграциями |
| M2 | LLM-основы | токены, context window, температура, роли, structured output, function calling со stub, стоимость, prompt caching | эндпоинт извлечения полей | заявка → структурированные данные |
| M3 | Контекст | сборка контекста, суммаризация, отбор релевантного | диалоговый до-сбор данных | агент дозапрашивает и помнит контекст |
| M4 | ML-минимум | фиксированные эмбеддинги, ближайшие соседи, правила приоритета, LLM | классификация типа и приоритета | тип и приоритет заявки |
| M5 | RAG | чанкинг, индексация, retrieval, реранкинг, ingestion, pgvector, гибридный поиск, faithfulness | валидация по базе знаний | ответ с основанием или отсутствие ответа; точный прайс через SQL |
| M6 | Агенты | состояние/память, HITL, LangGraph, ограниченный цикл tool use, MCP, guardrails | агентный workflow с инструментами | классифицировать→ветка типа→проверки→маршрут→действие/пауза |
| M7 | Оценка и безопасность | eval-датасеты, LLM-as-judge, регресс промптов, prompt injection | тесты поведения + защита от инъекций | измеримое качество и базовая безопасность |
| M8 | Нагрузка и стоимость | очереди, кеш (строковый+семантический), token budgets, retry/circuit breaker, LLM-fallback | обработка через очередь+кеш+деградация | локальный замер нагрузки, объяснимые отказы и расходы |
| M9 | Наблюдаемость | Langfuse, метрики, логи, алерты, бизнес-метрики | трейсинг и дашборд | видна стоимость/заявку, latency, доля авто/эскалаций |
