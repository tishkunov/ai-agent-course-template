# Пайплайн S1–S10

### 2.3 Пайплайн S1–S10 (кто реализует какой модуль)

Источник — [`course/contracts.md` §3 «Пайплайн S1–S10»](../../course/contracts.md#3-пайплайн-s1s10)
(таблица шагов и сквозных механизмов) и
[§8 «Порядок исполнения»](../../course/contracts.md#8-порядок-исполнения-c08) (фактический граф
прогона). Копии таблицы здесь нет.

Что важно помнить при ответах и ревью:

- Номера S — зоны ответственности. Классификация S4 идёт до извлечения S5; извлечение полей заявки выполняется только в ветке заявки.
- Ветка по `req_type` выбирается сразу после классификации: спам → `reject`; жалоба → оператор;
  вопрос → поиск по базе знаний; заявка → достаточность (S6) и валидация (S7).
- Валидация проверяет только известные условия. Неизвестное поле не даёт отрицательного результата
  проверки — см. `course/contracts.md` §6.
- Возврат из уточнения — новый прогон того же обращения: S1 корреляция → обновление контекста →
  повторная классификация → извлечение для заявки → достаточность и валидация → новое решение.
- M2 (извлечение) и M3 (до-сбор) — самостоятельные компоненты: их сценарии не требуют готового
  классификатора M4 и графа M6.
