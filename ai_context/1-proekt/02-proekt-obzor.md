# Проект: обзор и сущности

## 2. Проект целиком (полный контекст, не по кускам)

**Продукт.** Сервис, принимающий обращения (почта/форма/мессенджер) и доводящий их до результата: классифицирует → извлекает поля → валидирует по базе/справочникам → выбирает маршрут (авто / уточнение / эскалация оператору) → выполняет действие (заявка в БД, ответ клиенту, слот). Спорное и рискованное — человеку (HITL). Растёт по модулям — каждый модуль добавляет один слой над предыдущими, схемы расширяются по [плану контрактов](../../course/contracts.md).

### 2.1 Сущности

| Сущность | Ключевые поля/смысл |
|---|---|
| Обращение (request) | id, thread_key (доверенная идентичность диалога; общий anon не связывает клиентов), status, сырой вход, нормализованный текст, вложения, тип, извлечённые поля, missing[], client_id\|null, confidence по шагам, стоимость, история сообщений, timestamps |
| Клиент | справочник (`clients`) |
| Справочники/правила | прайс, зоны, регламенты (таблицы + KB для RAG) |
| Заявка (ticket) | один разрешённый заказ мастеру; вопрос/жалоба не создают ticket |
| Действие (action) | тип, ключ логического действия по M6.8, статус, сохранённый результат |
| Эскалация | обращение + решение оператора |
| Прогон (run) | event_id/run_id/request_id, шаги, call_id, итог; trace визуализирует запуск |

Обработка выбирает ветку после классификации: спам → reject без ответа; жалоба → оператор; вопрос → RAG; заявка → извлечение и проверки. Полная политика и статусы — [contracts](../../course/contracts.md), описание выше не заменяет её.
