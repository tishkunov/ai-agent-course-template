# Базовые принципы процесса + `.claudeignore`

## 8 принципов

1. **Оркестратор + воркеры** — главная сессия декомпозирует и маршрутизирует, сабагенты исполняют скоупные задачи. Модель — на выбор пользователя (ориентир — `../5-instrumenty/16-model-tiering.md`), включая модель оркестратора. См. `../4-process/17-orchestrator-workers.md`.
2. **Человеческие гейты на высоких ставках** — ИИ предлагает, человек одобряет; 🔴 HARD гейты останавливают пайплайн. См. `../4-process/15-human-gates.md`.
3. **Маленькие агенты, одна ответственность** — каждый воркер делает одну вещь хорошо.
4. **Доки как контракты** — агенты общаются через файлы в `docs/`, а не через чат.
5. **Гейт перед продолжением** — у каждой фазы вердикт pass/fail до старта следующей.
6. **Тесты — это гейты качества**, а не формальность; красные тесты блокируют merge.
7. **Контекст выживает в `docs/`, а не в чате** — Claude Code сам ужимает историю; долговременное состояние (требования, дизайн, план, решения, прогресс) должно лежать в `docs/*.md`, чтобы пережить компакт. Выходы оркестратора/воркеров пишутся в `docs/` по мере готовности, а не остаются неявными в транскрипте.
8. **`.claudeignore` — жёсткая граница** — агенты не читают `node_modules/`, `dist/`, `.env*`, lock-файлы: экономит токены и не даёт секретам попасть в контекст.

## Как это ложится на курс

| Принцип | В курсе |
|---|---|
| Доки как контракты | `docs/decisions.md` (ADR), `docs/progress.md`, `prompts/<step>_v<N>.md`, `course/M{n}-*/*` |
| Гейт перед продолжением | цикл из 7 шагов на пункт (`../4-process/12-process-raboty.md`) + интеграционная приёмка модуля (`../3-priyomka/10-kriterii-kachestva.md`) |
| Тесты — гейты | «Тесты» + «Готово, когда» в `course/M{n}-*/kriterii-priyomki.md`; регресс-гейт M7 |
| Контекст в docs | `ai_context/` держать открытым; решения — сразу в `decisions.md`, не «потом по памяти» |
| Маленькие агенты | не давать `implement` тут же себя ревьюить — шаг 3 и шаг 4 разные вызовы |

## `.claudeignore` для этого репозитория

Файла пока нет. **Осторожно:** синтетические данные в `data/` — это предмет курса, их игнорировать нельзя.

Разумный `.claudeignore`, если в репозитории появится код проекта (папку `data/` НЕ игнорировать):

```
# зависимости и сборка
.venv/
**/__pycache__/
**/*.pyc
node_modules/
**/node_modules/
dist/
build/

# окружение / секреты
.env
.env.*
!.env.example

# lock не для чтения агентом (но в git — да)
uv.lock
poetry.lock

# история выполнения миграций (не сами файлы миграций)
migrations/versions/__pycache__/

# шум редактора/ОС
.DS_Store
**/.DS_Store
*.log
```

Правило: если агенту нужно понять зависимость — читать её документацию, а не `node_modules`/`.venv`. Если нужна история схемы — читать исходники миграций, а не скомпилированный лог.
