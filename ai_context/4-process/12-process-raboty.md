# Процесс работы (памятка дня)

## 9. Процесс работы (ссылка)

Полный процесс — в `course/M0-start/zadanie.md` (роли, цикл из 7 шагов, промпт-контракты, политика расхождения/затыка, границы доверия). Модель для работы (и для сессии, и для сабагентов, и для «оркестратора») — любая удобная пользователю; `ai_context/5-instrumenty/16-model-tiering.md` даёт только ориентир по нагрузке, не обязателен. Здесь — краткая памятка на каждый день работы:

1. Открыть `course/M{n}-*/zadanie.md`, найти конкретный `M.x` (общие правила — `course/contracts.md`).
2. Собрать промпт-контракт: Цель+Требования+Контракты+Краевые случаи этого пункта из `course/M{n}-*/zadanie.md` + релевантные контракты из `../3-priyomka/11-stabilnye-kontrakty.md` как неизменяемые ограничения. При необходимости — `research`/`design`/`plan` (см. `../00-navigatsiya.md`, `../5-instrumenty/14-skilly-i-agenty-detalno.md`).
3. Получить код — скилл `implement` (агент `implementer`).
4. **Отдельным** вызовом — скилл `review` / `/code-review` (или сабагент `reviewer`) по `course/M{n}-*/detalnoe-review.md` (строка пункта + сводный чек-лист модуля), применяя `ai_context/3-priyomka/22-review-detalno.md` как чек-лист по стеку. Для M6.10/M7 — плюс `/security-review`.
5. Прогнать тесты пункта и проверить «Готово, когда» из `course/M{n}-*/kriterii-priyomki.md`.
6. Написать своими словами ответ на «Понять» в `docs/decisions.md` (ни один скилл это не закрывает).
7. Отметить пункт закрытым в трекере прогресса (см. `../4-process/13-treker-progressa.md`).

Приёмка модуля целиком — по разделу «Интеграционная приёмка» + Definition of Done в `course/M{n}-*/kriterii-priyomki.md`.
