# Выбор модели (ориентир, не правило)

**Модель — на выбор пользователя.** Ни один агент и ни один пункт `course/M{n}-*/` не привязан к конкретной модели. Какую модель ставить на сессию, какой моделью запускать сабагентов, какой моделью «оркестрировать» (вести главную сессию) — решает пользователь по удобству и бюджету. Таблица ниже — только ориентир «что обычно хватает», чтобы не переплачивать по привычке.

Практика по умолчанию для этого курса: **большую часть работы комфортно тянет средняя модель (Sonnet-класс).** Дорогая топовая модель нужна редко — только там, где реально много неоднозначности и цена ошибки высокая. Дешёвая быстрая модель (Haiku-класс) — для форматирования и сводок.

## Ориентир по нагрузке задачи

| Класс задачи | Обычно хватает | Примеры в курсе |
|---|---|---|
| Форматирование, сводка, шаблон по готовым значениям | дешёвая/быстрая | генерация описания PR, ужать отчёт |
| Скоуп чётко очерчен, вход определён, ошибку ловит следующий гейт | средняя | реализация пункта M.x, написание тестов, один проход код-ревью, разбивка одобренного дизайна на итерации |
| Много конкурирующих ограничений сразу; выход гейтит дальнейшую работу; неоднозначность требует суждения | топовая (по желанию) | ревью дизайна/плана на прочность, корневой анализ сложного бага, требования из очень сырого запроса |
| И высокие ставки, и высокая сложность в одном заходе; нужен весь контекст в один проход | максимальная (разово, по решению) | ревью большого диффа против всей кодовой базы; дизайн-ревью, затрагивающее ядро модели данных |

Это ориентир, а не обязанность. Если удобнее и по бюджету нормально — вести всё на одной средней модели тоже рабочий вариант.

## Проектные сабагенты и модель

В `.claude/agents/*.md` поле `model` намеренно не задано — каждый сабагент наследует модель, которую пользователь выбрал по умолчанию для сабагентов (или ту, что указана при запуске). Если хочется прижать конкретного сабагента к своей модели — добавить `model:` в его frontmatter вручную; это локальное решение пользователя, в контракт роли не входит.

По нагрузке (тот же ориентир, что выше):
- `analyst`, `plan-reviewer`, `final-reviewer`, `debugger` — ближе к «нужно суждение», комфортнее на модели посильнее, но не обязательно.
- `tester` и встроенные `implementer` / `planner` / `reviewer` — скоупная работа, средней модели обычно достаточно.

## Стоимость как тема курса

Стоимость на обращение — сквозная тема (шаг S «Стоимость», M2.8 → M8.7): токены и цена считаются из ответа и пишутся в `llm_calls` (M2.8), агрегат сходится (M2.8 «Ревью»), бюджеты реально отсекают (M8.7). Актуальные id и цены моделей семейства Claude смотреть через скилл `claude-api` (`../5-instrumenty/14-skilly-i-agenty-detalno.md`) — не по памяти.

## Контекст между запусками

Claude Code сам ужимает историю по мере приближения к лимиту — ручной `/compact` в середине не нужен. Что важно для длинных прогонов: держать долговременное состояние в `docs/*.md` (`requirements.md`, `tech-design.md`, `implementation-plan.md`, `decisions.md`, `progress.md`), а не в истории чата. Авто-компакт суммаризирует диалог, но не восстановит решение, которое не записали в файл.
